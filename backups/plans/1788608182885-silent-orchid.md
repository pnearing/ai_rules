# Plan: `agents-md-gen` — Ollama-powered AGENTS.md Generator

## Goal

A Python 3.14 CLI tool, developed in this repo, that generates an `AGENTS.md` for a target project from a language + framework + project idea (+ optional MCP list), grounded in this repo's rules corpus, using a local Ollama instance. Future v2: also generate `opencode.json` (MCP enablement), which will drive per-MCP instruction inclusion.

**Hard constraint:** the root `/home/streak/src/ai_rules/AGENTS.md` must never be modified or replaced — enforced in code AND verified in tests.

## Confirmed decisions

| Topic | Decision |
|---|---|
| Generation | Hybrid: rule corpus (every `.md` except `README.md` + root `AGENTS.md`) grounds an LLM generation pass |
| Corpus fit | Relevance filter + token budget (directory/category is primary signal) |
| Corpus layout | **Reorg first**: all rules under `rules/` subdivided by language; MCP gets its own structure |
| Ollama client | Official `ollama` Python package |
| Model selection | `--model` flag; if omitted, auto-detect installed models → interactive selection |
| Overwrite | Refuse if target exists unless `--force`; repo's own root AGENTS.md refuses even `--force` |
| CLI | Flags satisfy what they satisfy; wizard prompts for the rest. Idea via `--idea-file` or multiline interactive entry |
| Packaging | `pyproject.toml` at repo root, `src/agents_md_gen/` layout, `tests/` with pytest, Ruff, venv |

## Milestone 3 — Corpus + selection

Modules (all fully typed, Google docstrings, no comments unless needed):

```
src/agents_md_gen/
  __init__.py
  __main__.py       # python -m support
  constants.py      # defaults: budget margin, default output name, excluded paths, model fallback ctx
  corpus.py         # RuleFile dataclass + discover_rules(rules_root) -> list[RuleFile]
  selection.py      # score + pack to budget -> SelectionResult
  ollama_client.py  # Protocol + RealOllamaClient (isolated, mockable)
  prompt.py         # build_system_prompt(), build_user_prompt()
  wizard.py         # interactive collection of missing request fields
  safety.py         # overwrite checks + protected-path enforcement
  writers.py        # OutputWriter Protocol, AgentsMdWriter, OpenCodeJsonWriter (stub for v2)
  cli.py            # argparse + orchestration main()
```

Core types:

```python
@dataclass(frozen=True)
class RuleFile:
    path: Path          # relative to rules root, e.g. rules/python/pytest.md
    category: str       # "python", "general", "mcp/context7", ...
    description: str    # frontmatter description or empty
    content: str

@dataclass(frozen=True)
class GenerationRequest:
    language: str
    framework: str | None
    idea: str
    mcps: tuple[str, ...]   # empty allowed in v1
    output_path: Path
    model: str

@dataclass(frozen=True)
class SelectionResult:
    included: list[RuleFile]
    dropped: list[tuple[RuleFile, int]]   # (file, score) for --verbose reporting
    estimated_tokens: int
```

**Selection algorithm (deterministic):**
- Query tokens: lowercase word-tokens from language, framework, idea (deduped, stopwords removed).
- Score per file:
  - `category == language.lower()` → +50; `framework` in filename/description → +20
  - filename token overlap ×10; description/frontmatter overlap ×5
  - content heading/token overlap ×1 (scan first ~4 KB)
  - `category == "general"` or `category == "mcp/*"` (when MCPs requested) → base inclusion score
- Sort `(-score, path)`; always pack `general/` files first up to per-file excerpt cap.
- Budget: `usable = int(context_length * 0.5)` (leave room for instructions + output); `tokens ≈ chars // 4`. If model context unknown → conservative 8192. Optionally pass explicit `num_ctx` to Ollama within model max.
- Over-budget: truncate the lowest-priority files' excerpts (keep first N headings + rules) or drop entirely; record in `dropped`.

Tests: discovery on `tmp_path` fixture trees; frontmatter parsing (present/absent/malformed); scoring determinism; budget packing (mock context lengths); general-category always included.

## Milestone 4 — Ollama client wrapper

`ollama_client.py`:

```python
class OllamaClient(Protocol):
    def is_available(self) -> bool: ...
    def list_models(self) -> list[str]: ...
    def context_length(self, model: str) -> int | None: ...
    def generate(self, model: str, system: str, user: str, *, context_tokens: int) -> str: ...
```

- `RealOllamaClient` wraps the `ollama` package (`list()` / `show()` / `chat()` — **verify exact signatures and the context-length field via Context7 before coding**). Non-streaming, low temperature (~0.2), explicit timeout (e.g. 600 s) for long generations.
- Unreachable server → clean error with hint (`ollama serve`); unknown model → error + suggestion to run `--list-models`.
- Tests: fake client implementing the Protocol; error-path tests with `monkeypatch`-ed failures.

CLI extras: `--list-models` prints installed models and exits.

## Milestone 5 — Prompt builder + wizard

**Prompt:**
- System: "You are a senior {language} engineer... produce an AGENTS.md in markdown only" with hard rules (typing, testing, structure, docs, security) adapted per language from selected corpus.
- User: selected rule excerpts, each prefixed with `<!-- source: rules/python/pytest.md -->` citations, + language/framework/idea/MCP block + required output skeleton:
  1. Project overview (from idea)
  2. Coding practices & style (language/framework-specific)
  3. Testing practices
  4. Project organization / structure
  5. Documentation practices
  6. MCP usage (only listed MCPs; generic guidance in v1)
  7. Commands (build/test/lint placeholders per ecosystem)
- Output-only-markdown instruction; no preamble/fence stripping handled in `writers.py`.

**Wizard (`wizard.py`):**
1. Language (required, non-empty)
2. Framework (optional)
3. Idea (required): from `--idea-file` if given (error if unreadable), else multiline stdin prompt terminated by an empty line
4. MCPs (optional, comma-separated)
5. Output path (default `./AGENTS.md`)
6. Model: from `--model`, else list models from Ollama and prompt for numbered choice (non-TTY + no `--model` → graceful error telling which flags are required for scripted use)
- Tests: `monkeypatch` stdin/stdout; multiline termination; non-TTY error paths; flag-supplied values skip prompts.

## Milestone 6 — Safety + writers + CLI

**`safety.py`:**
- `ensure_writable(path, force)`: exists + not force → `RefusalError`; exists + force → allowed (except protected).
- `protected_repo_agents_md()`: walk `Path(__file__).resolve().parents` for the dir containing BOTH `pyproject.toml` and `AGENTS.md` (this repo's markers) → return its `AGENTS.md` path.
- Writing to the protected path is **refused even with `--force`** — clear error message. No override flag.
- `writers.py`: `OutputWriter` Protocol; `AgentsMdWriter` strips code fences if the model adds them, writes atomically (tmp file + `os.replace`). `opencode_json` stub for v2. `--dry-run` prints the generated markdown without writing.

**CLI flags:** `--language`, `--framework`, `--mcps`, `--output/-o`, `--model`, `--idea-file`, `--force`, `--dry-run`, `--list-models`, `--verbose` (show selection report), `--rules-dir` (default: packaged/repo `rules/` resolved relative to repo root; overridable).

Tests: overwrite refusal; `--force` allows non-protected overwrite; protected-path refusal with and without `--force` (temp-repo fixture with marker files); fence stripping; atomic write; end-to-end `cli.main()` with fake client writing to `tmp_path`.

## Risks / implementer notes

- **`ollama` package API drift** — resolve-library-id + query Context7 for `chat`, `list`, `show` signatures and context-length field before writing `ollama_client.py`; the Protocol isolates this.
- Context-length detection varies by model family; always fall back to 8192 and cap `num_ctx` to detected max.
- ~190-file mapping has judgment calls; ambiguous → `general/` (documented in the migration script's mapping dict for review).
- Small local models may produce weak output; skeleton-enforced prompting + docs recommending a coder model (e.g. qwen2.5-coder) mitigate.
- Moving `MCP/Context7/SKILL.md` affects only the repo copy; installed opencode skills live elsewhere — no functional impact.
- Python 3.14 + `ollama` package compatibility: verify install in the venv during Milestone 2.
- GPL v3 repo: the tool inherits the repo license; no license file changes needed.
